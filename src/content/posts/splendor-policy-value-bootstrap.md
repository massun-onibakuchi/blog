Splendor をプレイする AI を作っている。Splendor は、宝石トークンを集めて発展カードを購入し、そのカードから得られる割引や得点を積み上げていくボードゲームだ。

最終的には、ニューラルネットワークの予測を探索に組み込み、さらに自己対局から改善していくところまで持っていきたい。その最初の段階として、既存の手作り AI を「教師役」にして、**どの手を選ぶか**と**その局面から勝つか・引き分けるか・負けるか**を同時に学習する実験を行った。

今回いちばん重要だった結果は、学習を長く続ければ全体が良くなるわけではなかったことだ。手の選び方は終盤まで少しずつ教師に近づいた一方、勝敗予測は途中から明確に悪化した。

## 何を学習させたのか

モデルには二つの出力がある。

**policy** は、その局面で選べる合法手それぞれに「どれを選びたいか」という確率を出す。今回は教師役 AI の選択分布を真似するように学習した。

**value** は、その局面から見た最終結果を win / draw / loss の3クラスで予測する。探索では、この勝敗予測を「先を読んだとき、その局面がどれくらい良さそうか」の目安に使う予定だ。

教師役 AI は、手作りの評価関数と浅い先読みを組み合わせたものを使った。今回の学習データはすべてこの教師同士の対局から作り、モデル自身の自己対局データはまだ混ぜていない。いわば、自己対局を始める前の最初の足場を作る実験だ。

データは 4,096 個の初期配置から2対局ずつ生成し、合計 8,192 対局、478,194 手になった。同じ初期配置から派生した対局が学習用と評価用にまたがらないよう、初期配置単位で train / validation / test に分割した。

モデル本体は、プレイヤー、場のカード、貴族などを独立に圧縮してから考えるのではなく、**それらの関係を先に処理してから全体を要約する**構造にした。Splendor では「自分の資源でこのカードを買えるか」「相手がこのカードを先に取れそうか」「カードのボーナスが貴族の条件にどう効くか」のような関係が重要だからだ。

実装上はこのモデルを relational policy-value v2 と呼んでいるが、名前よりも「オブジェクト同士を見比べてから局面全体をまとめる」点が変更の中心になる。

- [relational policy-value v2 の実装](https://github.com/massun-onibakuchi/sml/commit/bf0efb7592c4d708c5929a6725ae12ece8ae41c8)

## 8,000 step 学習したが、採用したのは step 3,356 だった

学習は 8,000 optimizer step まで実行した。ここでいう **checkpoint** は、学習途中で保存したモデルの状態のことだ。

最終 step のモデルをそのまま採用するのではなく、学習に使っていない validation データで最も良かった checkpoint を選ぶルールにした。test データは、その選択が終わったあとに一度だけ評価するために分けている。

- [validation と test を分離した変更](https://github.com/massun-onibakuchi/sml/commit/36ae0a73a5f471d14aaf970d35cdabd615521438)
- [validation で best checkpoint を選ぶ変更](https://github.com/massun-onibakuchi/sml/commit/d039dc1640116ef9670ff2c3e5b76984036f1caa)

このルールで選ばれたのが step 3,356 の checkpoint だった。学習終了時の step 8,000 と比べると、なぜ途中のモデルを残す必要があったのかがはっきり分かる。

| Checkpoint | 全体 loss | policy loss | 勝敗予測 loss | 勝敗予測 accuracy |
| --- | ---: | ---: | ---: | ---: |
| **3,356（採用）** | **1.2824** | 0.9303 | 0.7043 | 65.86% |
| 8,000（学習終了時） | 1.4900 | **0.9120** | 1.1560 | 61.82% |

loss は小さいほど良い。policy loss だけを見ると、step 8,000 の方がわずかに良い。つまり教師の手を真似する能力は学習後半も改善していた。

一方で、勝敗予測の loss は 0.7043 から 1.1560 へ悪化した。step 3,356 から 8,000 の間に **64%悪化**している。全体 loss も 16%悪化した。

学習データ上の勝敗予測 loss は下がり続けていたので、これは典型的な過学習だった。最後まで学習したモデルだけを見ていたら、「より長く学習したのだからこちらが良い」と誤って採用していた可能性が高い。

## 教師の手はかなり真似できた

採用した checkpoint を、最後までモデル選択に使わず残しておいた test データで評価した。

policy の top-1 accuracy、つまり「モデルが一番選びたいとした手」と「教師の分布で一番強く推された手」が一致した割合は **68.15%** だった。教師が実際にサンプルして選んだ手との一致率も **65.38%** だった。

ただし、平均値だけでは見えない弱点もある。教師がほぼ一択だと考えている局面では top-1 accuracy は 97.8% だったが、複数の手に確率を広く配っている局面では 17.4% まで落ちた。

つまり、明確な局面では教師の判断をかなり再現できる一方、序盤のように複数の方針があり得る局面はまだ難しい。policy の 68.15% という数字を、そのまま「教師の68%の強さ」と読むことはできない。

## 勝敗予測にも信号はあるが、探索に十分とはまだ言えない

採用した checkpoint の勝敗予測 accuracy は test データで **63.26%** だった。学習データの勝敗比率だけを常に予測する単純な基準は 49.74% なので、局面から最終結果を読む信号は学べている。

ただし、この結果も局面によって差が大きい。ゲーム終了まで33手以上残っている局面では勝敗予測 accuracy は **52.7%**、最後の1手では **90.0%** だった。

探索で本当に欲しいのは、終盤だけでなく「まだかなり先がある局面でも、どちらの方向が有望か」を判断する value だ。今のモデルはそこがまだ弱い。

また、1対局の中にある多数の局面は同じ最終勝敗ラベルを共有する。24,542 個の test 局面を24,542個の完全に独立な標本とみなすと、結果を過信することになる。対局単位の依存を考慮して再確認すると、いくつかの指標では改善が明確に残ったものの、cross-entropy の改善はまだ不確実だった。

この実験から言えるのは、**教師の手の選び方と、教師が訪れる局面での勝敗に関する有用な信号を学べた**ところまでだ。

## 「学習できた」と「強くなった」は別の問い

今回の結果は、Splendor を強くプレイできることの証明ではない。

学習に使った局面は教師役 AI が訪れたものだけで、ニューラルネットワーク自身が探索したときに現れる局面はまだ評価していない。教師をかなり忠実に模倣できても、教師より強いとは限らないし、policy や value の offline 指標から Elo のような対局強度を推定することもできない。

次にやるべきことは、採用した step 3,356 のモデルを固定し、その予測を実際のゲーム木探索に組み込んで対局させることだ。まずランダムに手を選ぶ相手を安定して上回れるかを、席順を入れ替えた対局で測る。その結果が通って初めて、自己対局データを作る段階へ進む。

今回の収穫は、単に loss が下がったことではなかった。**「教師の手を真似する能力」と「局面の勝敗を読む能力は、学習中に同じようには伸びない」**ことが実測で分かった。

その違いを見逃さずに途中の checkpoint を選べたことが、最初の学習実験で得た一番大きな進捗だった。
